# Kiro 提示词策略与验收

## 行为契约

本策略只调整 Kiro 适配层的提示词组织，不改变公开请求/响应协议、认证、账号池、代理路由、工具执行、重试边界或收费数据。默认不注入固定身份或“禁止讨论 Kiro”等文案，不整体替换客户端 system，不强制所有写入都拆成微步骤。

- `KIRO_IDENTITY_PROMPT` 默认空字符串；显式配置才追加自定义文案。
- `KIRO_TOOL_DESCRIPTION_MODE=reference`：超过 9216 UTF-8 字节的工具说明完整移到逻辑 system 的工具文档区，字段内保留确定性的引用。`error` 返回 400，不提供静默截断模式。该字节值是适配层的保守字段预算，不是对所有 Kiro 端点限制的保证。
- 转移后的文档仍占输入空间。最终请求超出 `KIRO_MAX_PAYLOAD_BYTES` 时按现有规则返回 413；旧历史裁剪仍必须显式开启，不能裁剪当前输入、工具参数或系统区来掩盖超限。
- `KIRO_TOOL_SIZE_HINTS=true`：仅同时具备文件修改名称、文件上下文和内容参数信号的工具收到大小提醒。读取、搜索、任意命令、用户创建和数据库写入没有全局拆分指令。
- `KIRO_TOOL_ARG_SOFT_LIMIT_BYTES=16384`：UTF-8 字节参考目标，不是真实上游硬限制。保持小操作单次调用，不牺牲原子性，不改变工具文档的执行语义。
- `KIRO_THINKING_PROMPT_MODE=auto`：只有显式原生 thinking 控制才替代兼容 XML；仅有 effort 字段不是思考已启用的证据。当前映射只构造 effort，因此 Claude 显式思考请求继续保留启用 XML，不向其他模型添加 Claude XML。自适应兼容路径保留既有 XML 格式，并与结构化 effort 使用统一解析后的强度来源；XML 的旧兼容集合仍为 low/medium/high，更高档位保留在支持它们的结构化字段中，不凭空扩展 XML 协议。`legacy` 强制保留兼容 XML，`off` 仅关闭网关 XML；都不删除客户端已有指令或结构化 effort。这里没有新增未经验证的原生 thinking 请求字段，也不保证 XML 数字是上游真实思考额度。
- Claude 强度来源优先级：`reasoning_effort` > `output_config.effort` > 活跃 `thinking.effort` > 既有模型默认值。空白字符串视为未设置；显式不支持的强度按已有模型规则回退，不擅自选择下一来源。`thinking.type=disabled` 或没有启用思考时，嵌套的 `thinking.effort` 不会隐式启用控制。仅 XML 的旧模型也使用相同来源优先级。GPT 保留原有命名空间和禁用逻辑。
- `KIRO_TRUNCATION_RECOVERY=true`：仅在正常结束的纯正文响应被网关实际观察到 `max_tokens` 后记录摘要；只有匹配同一模型、客户端 system、工具定义、完整历史和可用用户/会话标识的下一条用户消息得到恢复说明。不增加假的助手确认、不制造 tool_result、不自动继续生成。

对于以 assistant 开头的恢复历史，只在上游协议需要时补最小的用户占位消息，不恢复旧身份前缀。首条历史或当前消息里的孤立工具结果仍按已有规则保留为带状态的文本，图片及其关联说明不丢失；有真实配对的工具结果仍作为 toolResults 发送。

## 截断与工具安全

记录按 Kiro 服务实例隔离，只保存 SHA-256 摘要和到期时间，最多 64 条，TTL 10 分钟；不保存生成文本或工具参数。通知可在同一个请求重试时重复查询，不消耗证据。最近助手轮次变更、过期、实例/账号切换或历史压缩后无法匹配，则不添加通知。

同一请求上下文与正文的后续纯文本重试若以 `end_turn` 或 `stop_sequence` 完整结束，会使对应旧截断记录失效。不清空其他用户/会话或不同正文分支的记录，不依据未知结束原因、取消或不完整响应清除证据。普通完成且没有待核对记录时，不计算整个请求的摘要，避免增加常规响应处理开销。

只有完整的 `message_stop` 以及可见正文才建立记录。没有显式上限信号的普通 EOF、思考-only 的最小空白文本、取消、中途断线、残帧和工具调用不建立正文截断记录。UTF-16 代理对跨流片段时，输出摘要仍等价于完整 UTF-8 文本。

工具参数继续在验证完成后才发出；残缺 JSON 和残缺事件帧仍然是 502 完整性失败。错误附上适用的恢复说明，但不修复参数、不假装工具已执行、不自动重放此前完成的调用。响应中的结束原因和 token 用量保持原样，通知只出现在匹配的后续请求中。

## 提示词优先级与去重

Kiro 适配层的逻辑 system 会按现有协议组织进用户输入/历史；添加 XML 或 Gateway 标签不代表取得真正的服务端 system 优先级。客户端原文不被过滤或裁剪；仅对网关添加的完整文档/文案做精确去重，重试不会在输入对象里积累副本。超长工具名仍通过已有映射恢复到客户端名称，文档用相同的上游别名引用。

外部提示词文件是独立入口。`SYSTEM_PROMPT_MODE=append` 保留客户端 system；`overwrite` 仍是明确的全局覆盖配置，本策略不偷偷改变已部署的私有配置文件。示例文件采用 `append`，与服务默认值一致。

## 本地验证与上线 A/B

本地测试覆盖身份默认关闭、指令保留、UTF-8 边界、工具说明尾部、稳定引用、缓存点、工具别名、输入不可变、预算拒绝、条件性提示、思考模式和截断证据隔离，并复用原有 CRC、流式、取消、工具参数完整性、图片和代理回归测试。

验证命令（不启动真实账号服务）：

```sh
npm test -- --runInBand --testPathIgnorePatterns tests/api-integration.test.js
```

`tests/api-integration.test.js` 需要另行启动真实 API 服务并配置对应渠道，不能把未运行的线上集成验收算作通过。

上线时用同模型、同任务集比较：

1. 保留客户端指令，关闭大小提醒和恢复通知；
2. 仅开启大小提醒；
3. 再开启证据驱动的恢复通知；
4. 分别验证 `auto` 与确实需要的 `legacy` 思考路径；只有确认目标 Kiro 路由有独立原生启用控制后，才考虑用 `off` 关闭兼容启用 XML。

保持长工具说明不丢失；记录任务完成率、产出测试通过率、工具格式错误率、首个可见输出时间、总耗时和真实 token 用量。不要以思考文本更长、身份自述或模拟预算数字证明底层模型能力提升。

这些本地测试不代表已验证真实 Kiro 的模型能力、具体端点字段支持、工具成功执行或生产性能改善。
